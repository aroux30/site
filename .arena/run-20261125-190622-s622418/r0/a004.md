## 1. Socratic Architectural Interrogation: 6 Expert Questions & Answers

To guarantee that the solution solves root causes rather than masking symptoms, we begin with the six foundational architectural questions an expert systems architect must answer before writing code:

### Question 1: Why did `form_container` fail to expose its action endpoint and validation message controls in the Inspector, despite having them implemented in `inspector-panel.tsx`?
**Expert Answer**: In `inspector-panel.tsx`, lines 136–140 defined `isSpecializedContainer` as:
```typescript
const isSpecializedContainer =
  selectedElement.type === "container" &&
  ["nested_tabs", "nested_accordion", "off_canvas", "popup_builder"].includes(String(selectedElement.widgetType));
```
Because `form_container` was omitted from this list, selecting a `form_container` satisfied `selectedElement.type === "container" && !isSpecializedContainer`. This immediately routed execution into the generic flexbox/grid layout controls branch and returned early. Consequently, `case "form_container":` at lines 1160–1191 was dead code at runtime. Adding `"form_container"` to `isSpecializedContainer` unblocks the switch statement, allowing the user to configure `submit_url`, `success_message`, and `error_message`.

### Question 2: Why were container-based compound widgets (`nested_tabs`, `nested_accordion`, `off_canvas`, `popup_builder`) silently degrading in SSR output into plain unstyled `<section>` elements?
**Expert Answer**: In `block-registry.ts`, `nested_tabs`, `nested_accordion`, `off_canvas`, and `popup_builder` are defined with `type: "container"`. When serialized to the backend AST and compiled by `ast_compiler.py`, `_compile_element` branches strictly on `el.type`:
```python
if el.type == "container":
    return cls._compile_container(el, is_authenticated=is_authenticated)
elif el.type == "widget":
    return cls._compile_widget(el)
```
In `_compile_container`, only `is_form = el.widget_type == "form_container"` was handled. The compiler rendered a generic `<section>` and naively concatenated child elements. The specialized compilation logic for `nested_tabs`, `nested_accordion`, `off_canvas`, and `popup_builder` had been placed in `_compile_widget`, which was never reached for containers. The fix requires implementing first-class specialized container compilation inside `_compile_container`, generating interactive tab navigation pills, collapsible accordion item wrappers, lateral drawer structures, and modal overlays directly around container children.

### Question 3: How do we prevent runtime crashes when form controls receive newline-separated string payloads or non-array inputs from copy-paste or external ASTs?
**Expert Answer**: In `canvas-element.tsx`, `form_select` executed `options.map(...)` assuming `props.options` is always an array (`const options = (props.options as string[]) || [...]`). If `props.options` was set as a raw newline-delimited string (e.g., from an import or manual state patch), `.map` threw an unhandled `TypeError: options.map is not a function`, crashing the entire canvas iframe. The solution is defensive normalization: coerce options into a clean array across all layers—split strings on `[
،,]`, extract `{label, value}` objects safely, and guarantee an array before rendering.

### Question 4: Why was `widget_type == "toggle"` duplicated in `ast_compiler.py` and how does property drift (`open` vs `default_open` vs `is_open`) break WYSIWYG parity?
**Expert Answer**: `ast_compiler.py` contained two conflicting `elif widget_type == "toggle":` blocks (line 1004 and line 1214). The earlier block shadowed the second. Furthermore, `inspector-panel.tsx` saved `default_open`, `canvas-element.tsx` checked `item.open`, and `ast_compiler.py` checked `itm.get("default_open")`. This property drift meant a toggle set as open in the inspector appeared closed in the canvas or SSR output. We must deduplicate the compiler handler and implement a unified property cascade: `item.default_open ?? item.open ?? item.is_open ?? (idx === 0)`.

### Question 5: How does the 4-layer architecture guarantee zero horizontal overflow and maintain Radix z-index >= 150 across Persian RTL layouts at 1280x720 and 1440x900?
**Expert Answer**: Zero horizontal overflow is achieved by enforcing `w-full min-w-0 max-w-full overflow-x-hidden` on all parent inspector flex chains and applying `dir="rtl"` with logical margins (`pe-8`, `ps-2`, `ms-1`) instead of hardcoded `left`/`right`. Radix primitives (Select, Popover, Tooltip) must render in portals with `z-index: 150` or higher to clear both the studio sidebars and the iframe canvas ceiling (`z-index: 20`–`50`).

### Question 6: What are the exact determinism contracts for the 4 sensors (`scroll_audit.json`, `menu_open_proof.json`, `semantic_widget_audit.json`, `mutation_report.json`) in Weight 2?
**Expert Answer**:
- `scroll_audit.json`: Asserts `scrollWidth <= clientWidth` (0px horizontal overflow) on both inspector and canvas across viewports 1280x720 and 1440x900, with `min-h-0` flex chains verifying vertical scrollability (`scrollTop > 0` on wheel).
- `menu_open_proof.json`: Asserts all select triggers, comboboxes, and popovers achieve `aria-expanded="true"` or `data-state="open"` with rendered portal bounding boxes > 20x20px and `z-index >= 150`.
- `semantic_widget_audit.json`: Asserts valid `<svg>` vector rendering (no raw text fallback strings like "star"), valid Persian directional guidance ("پنل سمت راست"), and complete image dimensions (`naturalWidth > 0`).
- `mutation_report.json`: Asserts that an active property nudge in the inspector triggers an immediate DOM style/text change in the iframe with `pixelmatch` changed pixels > 0, 0 console errors, 0 network 4xx/5xx errors, and 0 React hydration mismatches.

- **AC-L4.1**: `ast_compiler.py` compiling `form_container` MUST produce `<form action="..." method="POST" data-form-container="true">` containing the anti-spam honeypot `<input type="text" name="_hp_website" style="display:none !important;" tabindex="-1" autocomplete="off" aria-hidden="true" />`.
- **AC-L4.2**: `ast_compiler.py` compiling `nested_tabs` container MUST output `<div class="builder-nested-tabs">` containing navigation buttons and tab panes with the first pane active and remaining panes hidden.
- **AC-L4.3**: All user-controlled text strings (`label`, `placeholder`, `title`, `content`) MUST be sanitized via `html.escape` to eliminate XSS injection vulnerabilities.
- **AC-L4.4**: Duplicate `toggle` compilation in `ast_compiler.py` MUST be eliminated, unifying open-state evaluation.

### Phase 4: Deterministic 4-Sensor Verification Criteria
- **Sensor 1 (Scroll)**: Horizontal overflow == 0px at 1280x720 and 1440x900. Vertical scroll offset > 0px on wheel event.
- **Sensor 2 (Menu Proof)**: Select dropdown open verified with `z-index >= 150`, unblocked by iframe ceiling.
- **Sensor 3 (Semantic)**: Zero raw glyph strings ("star" -> `<svg>`), RTL direction indicator refers to "پنل سمت راست".

## 3. Explicit Architectural Trade-Offs

Every sound engineering choice involves deliberate trade-offs. The following decisions are made to align with production constraints:

| Architectural Decision | Chosen Approach | Alternative Considered | Deliberate Trade-Off & Justification |
| :--- | :--- | :--- | :--- |
| **Specialized Container Content Hierarchy** | Show specialized widget controls first in Content tab; keep layout controls (dimensions, padding, background) in Style tab. | Duplicate all flex/grid layout controls inside Content tab alongside specialized controls. | **Gives up**: Quick access to flex direction inside Content tab.<br>**Gains**: Zero vertical scroll bloat, clean mental model separating *What* (Content) from *How it looks* (Style). |
| **SSR Accordion & Toggle Engine** | Use semantic HTML5 `<details>` and `<summary>` tags with CSS `:open` pseudo-class and Tailwind chevrons. | Inject inline JavaScript event handlers or hydration script blocks into SSR HTML. | **Gives up**: Complex JS transition animations without hydration.<br>**Gains**: 100% accessible, zero-JS functionality, instant time-to-interactive, and zero XSS attack surface. |
| **Countdown SSR Calculation** | Pre-compute static time diff on server render with Persian numerals; activate live ticker upon client hydration. | Render empty placeholders or zeroed values during SSR until client loads. | **Gives up**: Dynamic live tick on pure static HTML without JS.<br>**Gains**: Complete SEO indexing, zero layout shift (CLS = 0), and immediate readable preview. |
| **Defensive Option Coercion** | Automatically parse and split strings into arrays across canvas and compiler layers. | Reject malformed options with strict validation error. | **Gives up**: Strict schema purism.<br>**Gains**: Resilient authoring experience—user can type or paste options separated by commas or newlines without breaking the studio. |

## 6. Comprehensive Analytical Documentation

### 6.1 5-Whys Root Cause Analysis

#### Defect DEFECT-W2-01: Form Container Controls Hidden in Inspector
1. **Why was the user unable to configure form action URLs and response messages in the inspector?**
   Because the Content tab for `form_container` displayed only container flexbox/grid layout controls (direction, wrap, gap) without any form-specific settings.
2. **Why did it display only generic container controls?**
   Because `renderContentControls` in `inspector-panel.tsx` evaluated `if (selectedElement.type === "container" && !isSpecializedContainer)` and returned early before reaching the widget switch statement.
3. **Why did `!isSpecializedContainer` evaluate to true for `form_container`?**
   Because `isSpecializedContainer` was defined with a hardcoded list: `["nested_tabs", "nested_accordion", "off_canvas", "popup_builder"]`, omitting `"form_container"`.
4. **Why was `form_container` defined as a container in the first place?**
   Because in modern web builders (e.g., Elementor Form Container), a form must act as a flexbox drop-zone capable of hosting multiple child input fields, select dropdowns, textareas, and submit buttons.
5. **What is the root architectural fix?**
   Include `"form_container"` in `isSpecializedContainer`, allowing execution to fall through to `case "form_container":` while allowing layout and styling to be managed cleanly in the Style tab.

#### Defect DEFECT-W2-02: SSR Output Stripping Interactive Container Markup
1. **Why did `nested_tabs` and `nested_accordion` lose their tab buttons and accordion headers on server-rendered pages?**
   Because the rendered HTML was just a plain `<section>` with child containers dumped in sequence without header pills or collapsible items.
2. **Why was the specialized HTML missing from SSR?**
   Because `_compile_container` in `ast_compiler.py` only checked `if is_form:` and otherwise simply concatenated `cls._compile_element(child)`.
3. **Why didn't the compiler call `_compile_widget` where `nested_tabs` and `nested_accordion` were implemented?**
   Because `_compile_element` dispatched strictly on `el.type == "container"`, and these compound elements have `type: "container"` in `block-registry.ts`.
4. **Why was this disparity not caught earlier?**
   Because initial unit tests tested `_compile_widget` directly with mock elements having `type: "widget"`, failing to test real registry instances where `type: "container"`.
5. **What is the root architectural fix?**
   Elevate compound containers to first-class citizens in `_compile_container`, compiling headers, navigation pills, drawers, and modal backdrops around child elements in SSR.
