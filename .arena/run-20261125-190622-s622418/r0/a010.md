## 2. First Principles Architectural Audit (4-Layer Breakdown)

## 2.1 First Principles Foundation
From first principles, a visual page builder is a bidirectional state compiler:
Visual AST <=> AST Compiler / Inspector Dispatch <=> DOM / SSR Markup.

If any layer makes unverified assumptions about data shapes (e.g. assuming container widgets only compile via `_compile_widget` when the AST assigns them `type: "container"`), the pipeline fractures. The builder then displays components on the canvas that either fail to compile in SSR, drop changes on page reload, or crash the server.

## 3. Options Matrix & Strategic Decision

To reach 100% parity with maximum execution velocity and architectural rigor, three architectural options were evaluated.

## 3.1 Options Evaluation

- **Option A: Monolithic Patching (Ad-hoc Quick Fixes)**  
  Fix individual broken lines in `inspector-panel.tsx`, `canvas-element.tsx`, and `ast_compiler.py` without restructuring container compilation routing.
- **Option B: Unified 4-Layer Container-Widget Dispatch Architecture (Selected)**  
  Unify interactive container widgets (`nested_tabs`, `nested_accordion`, `popup_builder`, `off_canvas`) inside `_compile_container`, remove duplicate switch cases and dead compiler branches, provide defensive dictionary unpacking in `ast_compiler.py`, and standardize `data-testid` test harnesses across all 14 widgets.
- **Option C: Full Subcomponent Decoupling & Micro-Plugins**  
  Extract every single widget inspector control and canvas renderer into independent files (`inspector-form-input.tsx`, `canvas-form-input.tsx`, etc.).
