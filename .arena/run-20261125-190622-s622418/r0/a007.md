### 4. Analytical Documentation

#### 4.1 5-Whys Root Cause Analysis

**Core Defect**: When a user selected a `form_container` in the Visual Builder studio, the Inspector panel displayed generic Flexbox/Grid container layout controls instead of form submission configuration (`submit_url`, `success_message`, `error_message`).

1. **Why were the form action and message inputs missing from the Inspector panel?**
   Because `renderContentControls` inside `inspector-panel.tsx` evaluated `selectedElement.type === "container"` and returned the generic layout controls early, never reaching `case "form_container":`.

2. **Why did `renderContentControls` return early for `form_container`?**
   Because `isSpecializedContainer` was defined as:
   `["nested_tabs", "nested_accordion", "off_canvas", "popup_builder"].includes(String(selectedElement.widgetType))`
   which omitted `"form_container"`.

3. **Why was `form_container` created as a container rather than a leaf widget?**
   Because a form must contain child input widgets (`form_input`, `form_select`, `button`), requiring `type: "container"` to support child insertion, drag-and-drop, and tree nesting.

4. **Why was `form_container` omitted from the specialized container whitelist?**
   During the initial Elementor parity sprint, specialized containers were treated solely as multi-pane layout components (`nested_tabs`, `nested_accordion`), while form containers were mistakenly assumed to be handled by the widget switch branch.

5. **Root Cause Solution**:
   Add `"form_container"` to `isSpecializedContainer`, ensuring it reaches its dedicated content controls. Simultaneously, provide dual control panels for all specialized containers so users can configure both their specific domain attributes and their underlying container flex/grid layout properties (gap, direction, alignment).
