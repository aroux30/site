### 1. Adversarial Reviewer Vulnerability Audit & Defense Architecture

To ensure failure-proof resilience under hostile inputs, we picture the harshest expert reviewer trying to tear the architecture apart, write their attacks down first, and build our defenses backwards from them.

#### Attack Vector 1: Dead-Code Inspector Trap on Specialized Form Containers
- **Vulnerability**: In `frontend/components/admin/builder/inspector-panel.tsx` (lines 136–140), `isSpecializedContainer` checks if `selectedElement.type === "container"` and matches against `["nested_tabs", "nested_accordion", "off_canvas", "popup_builder"]`. Because `form_container` is registered with `type: "container"` in `block-registry.ts` (line 230), it is evaluated as a generic container and early-returns flex/grid layout controls. The dedicated `case "form_container":` at line 1160 is unreachable dead code.
- **Architectural Defense**: Extend `isSpecializedContainer` to include `"form_container"` and merge form action parameters (`submit_url`, `success_message`, `error_message`) with flex/grid container layout controls.

#### Attack Vector 2: State Corruption via Malformed or Empty Array Collections
- **Vulnerability**: In `accordion`, `tabs`, `toggle`, `form_select`, and `form_radio`, if `props.items`, `props.tabs`, or `props.options` is corrupted to `null`, `undefined`, or a non-array primitive, `items.map()` or `items.filter()` throws an unhandled runtime error (`TypeError: items.map is not a function`), crashing the Inspector panel and iframe canvas.
- **Architectural Defense**: Implement defensive array coercion across all 4 layers (`Array.isArray(x) ? x : []`), guarantee safe fallbacks, and prevent deleting the final remaining item to maintain interactive continuity.

#### Attack Vector 3: Semantic NaN Leak in Countdown Timer Calculations
- **Vulnerability**: If `props.target_date` is empty, malformed, or set in the past, naive date difference logic generates `NaN` for days, hours, minutes, and seconds, which renders as `NaN:NaN:NaN:NaN` on canvas and SSR, causing `semantic_widget_audit.json` to reject the build.
- **Architectural Defense**: Enforce strict `isNaN(targetTime)` guards in `canvas-element.tsx` and Python `try...except` parsing in `ast_compiler.py`, automatically clamping elapsed timers to Persian zeroes (`"۰۰"`).

#### Attack Vector 4: Nested Form Injection & Cross-Site Scripting (XSS)
- **Vulnerability**: An attacker supplying `submit_url="javascript:stealToken()"` or unescaped HTML quotes in option labels could execute arbitrary scripts in SSR HTML fallback output. Furthermore, placing a `form_container` inside another `form_container` violates HTML5 specifications and causes silent form field drops.
- **Architectural Defense**: Validate URL protocols (enforce relative paths `/` or `https://`), enforce HTML entity escaping via `html.escape()` on all labels, placeholders, and options in `ast_compiler.py`, and introduce `validate_form_structure()` in `builder_validation.py` to forbid nested forms.

#### Attack Vector 5: Z-Index Collision & Horizontal Overflow at 1280x720 / 1440x900
- **Vulnerability**: Rich form dropdowns (`Select`, `Popover`) inside the Inspector panel can render with low z-index (< 100), becoming occluded by the canvas iframe. Furthermore, long option labels without wrapping cause horizontal scroll traps (`scrollWidth > clientWidth`).
- **Architectural Defense**: Enforce `z-index >= 150` on all Radix portals, configure `overflow-x-hidden` on inspector wrappers with `truncate` on text labels, and ensure `min-h-0` flex chains throughout.

### 6. 5-Whys Root Cause Analysis

**Core Defect (DEFECT-W2-01)**: `form_container` content controls missing from Inspector panel Content tab when form container is selected.

1. **Why were `submit_url`, `success_message`, and `error_message` not displayed when selecting a Form Container?**
   Because the Content tab rendered generic Flexbox/Grid container layout controls instead of form-specific controls.
2. **Why did the Inspector render generic container layout controls?**
   Because line 140 of `inspector-panel.tsx` evaluated `if (selectedElement.type === "container" && !isSpecializedContainer)` and returned early before reaching line 1160 (`case "form_container":`).
3. **Why was `isSpecializedContainer` false for Form Container?**
   Because `isSpecializedContainer` at line 138 explicitly checked only `["nested_tabs", "nested_accordion", "off_canvas", "popup_builder"]`, omitting `"form_container"`.
4. **Why was Form Container registered as `type: "container"?**
   Because form fields (`form_input`, `form_select`, `form_checkbox`) must be nested as child elements inside the form container to guarantee DOM encapsulation and layout structure.
