# شکست import در ماژول settings — ۲۰۲۶-۱۰-۰۷

این سند با اصول ASD-STE100 نوشته شده است: جمله‌های کوتاه، صدای فعال، یک واژه برای یک مفهوم.

---

## ۱. مشکل چه بود؟

بک‌اند از بوت سرد ناتوان شد.

پیام خطا:

```
ImportError: cannot import name 'MaintenanceSetRequest'
from 'app.modules.settings.schemas.settings'
```

سرور در حال اجرا هنوز سالم بود. دلیلش این است که کد قدیم را لود کرده بود.

اما با اولین ری‌استارت، بک‌اند بالا نمی‌آمد.

---

## ۲. ریشهٔ مشکل چه بود؟

دو فایل ناسازگار شده بودند.

| فایل | وضعیت |
|---|---|
| `settings/schemas/settings.py` | دو کلاس حذف شده بودند |
| `settings/api/routes.py` | هنوز آن دو کلاس را import می‌کرد |

کلاس‌های حذف‌شده:

- `MaintenanceStateResponse`
- `MaintenanceSetRequest`

مسیرهای `/public/maintenance` و `/admin/maintenance` به این کلاس‌ها نیاز دارند.

بقیهٔ فیچر سالم بود: سرویس `maintenance_service.py` و خود مسیرها.

---

## ۳. این مشکل چطور پیدا شد؟

هیچ ابزاری آن را در زمان اجرا نگرفت.

سرور قدیم سالم کار می‌کرد.

**گیت‌ها آن را گرفتند.** سه گیت شکست خوردند:

- `setting value shapes serialize`
- `audit change capture wired into boot`
- `endpoint annotations resolve at runtime`

گیت سوم بوت کامل را import می‌کند. پس `ImportError` را دید.

---

## ۴. راه‌حل چه بود؟

دو کلاس به `settings/schemas/settings.py` برگشتند.

دقیقاً مطابق نسخهٔ اصلی. فیلدها با `as_dict()` سرویس هم‌خوان‌اند.

---

## ۵. راستی‌آزمایی

| بررسی | نتیجه |
|---|---|
| import بک‌اند | سبز |
| بوت کامل ASGI | سبز |
| ۷ گیت | ۷ از ۷ سبز |
| `GET /settings/public/maintenance` | `200` |
| `POST /settings/admin/maintenance` بدون ورود | `401` |
| چرخهٔ کامل روشن/خاموش | کار کرد |
| `tsc` فرانت‌اند | بدون خطا |
| ۴۰ تست فرانت‌اند | سبز |

### آزمون چرخهٔ کامل

```
before: {"active":false,...}
set ON  -> 200 {"active":true,"minutes":10,"reason":"تست کوتاه"}
set OFF -> 200 {"active":false,...}
after:  {"active":false,...}
```

سرویس ۵ دقیقه را به ۱۰ گرد می‌کند. این رفتار درست است.

---

## ۶. یک نقص دوم در خود اجراکنندهٔ گیت

`run_gates.py` هنگام گزارش شکست **کرش می‌کرد**.

دلیل: گیت‌ها فارسی چاپ می‌کنند. کنسول ویندوز `cp1252` است.

پس `sys.stdout.write(proc.stdout)` خطای `UnicodeEncodeError` می‌داد.

نتیجه: به‌جای نام‌بردن از گیت شکست‌خورده، فقط یک crash دیده می‌شد.

### اصلاح

هر دو stream در ابتدا به UTF-8 تنظیم می‌شوند.

### آزمون اصلاح

خرابی را دوباره تزریق کردم.

نتیجه: اجراکننده حالا **سه گیت را نام می‌برد** و خلاصه می‌آورد.

بعد فایل را برگرداندم. گیت‌ها سبز شدند.

---

## ۷. نکته‌های مهم

۱. یک `ImportError` در زمان بوت، هیچ ابزار زمان‌اجرایی نمی‌بیند. گیت‌ها آن را گرفتند.

۲. سرور در حال اجرا، کد قدیم را نگه می‌دارد. پس یک ویرایش غلط فوراً دیده نمی‌شود.

۳. چند سشن موازی روی این درخت کار می‌کنند. فایل‌های settings در ۲۱:۴۹ و ۲۲:۰۳ تغییر کردند.

۴. یک اجراکنندهٔ گیت که هنگام گزارش شکست کرش کند، از هیچ گیت هم بدتر است.

---
