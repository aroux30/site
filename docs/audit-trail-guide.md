# راهنمای صفحهٔ «گزارش رویدادها»

این سند با اصول ASD-STE100 نوشته شده است: جمله‌های کوتاه، صدای فعال، یک واژه برای یک مفهوم.

---

## ۱. این صفحه چیست؟

این صفحه تاریخچهٔ کارهای مهم سیستم را نشان می‌دهد.

هر ردیف یک کار انجام‌شده است.

سیستم هر ردیف را خودکار ثبت می‌کند.

کاربر نمی‌تواند ردیف‌ها را ویرایش یا حذف کند. این صفحه فقط نمایش می‌دهد.

برای دیدن این صفحه مجوز `audit:read` لازم است.

---

## ۲. تب «رویدادها»

این تب همهٔ رویدادهای ثبت‌شده را نشان می‌دهد.

ردیف‌ها از جدید به قدیم مرتب می‌شوند.

### فیلدهای هر ردیف — نمای بسته

| فیلد | معنی |
|---|---|
| عملیات | نام کار. مثال: `cms_page.created` یعنی یک صفحه ساخته شد. |
| منبع | نوع چیزی که تغییر کرد. مثال: `user` یا `cms_page`. |
| کاربر عامل | نام یا شمارهٔ کسی که کار را انجام داد. |
| IP | نشانی شبکهٔ دستگاه عامل. |
| تاریخ | زمان رویداد. تقویم شمسی است. |

### فیلدهای بیشتر — نمای باز

برای دیدن جزئیات، روی ردیف بزنید.

| فیلد | معنی |
|---|---|
| شناسهٔ درخواست | کد یکتای درخواست وب. برای پیگیری در لاگ سرور به‌کار می‌رود. |
| مرورگر | نام و نسخهٔ مرورگر عامل. |
| قبل | مقدارهای قبلی. قالب JSON دارد. |
| بعد | مقدارهای جدید. قالب JSON دارد. |
| داده تکمیلی | اطلاعات اضافی رویداد. قالب JSON دارد. |

### فیلترها

- کادر «فیلتر عملیات»: بخشی از نام عملیات را بنویسید. مثال: `cms_page`.
- کادر «منبع»: نام منبع را بنویسید. مثال: `user`.

صفحه بیست‌وپنج ردیف در هر صفحه نشان می‌دهد. دکمه‌های «قبلی» و «بعدی» صفحه را عوض می‌کنند.

---

## ۳. تب «تاریخچه تغییرات فیلدها»

این تب تغییر مقدار فیلدها را نشان می‌دهد.

مثال: تغییر قیمت یک محصول.

سیستم فقط موجودیت‌های ردیابی‌شده را ثبت می‌کند.

### موجودیت‌های ردیابی‌شده — شش مورد

۱. محصول ۲. واریانت ۳. تخفیف

۴. قاعده سفارش مجدد ۵. کیف پول ۶. قاعده قیمت‌گذاری

### فیلدهای هر ردیف

| فیلد | معنی |
|---|---|
| موجودیت | نوع رکورد. مثال: «محصول». |
| شناسه | کد کوتاه رکورد. |
| تعداد فیلد | تعداد فیلدهای تغییرکرده. |
| تاریخ | زمان تغییر. |

### پس از باز کردن ردیف

| فیلد | معنی |
|---|---|
| عملیات | ایجاد، ویرایش یا حذف. |
| منبع تغییر | API، پنل مدیریت، سرویس یا Seed. |
| عامل | کاربر، سیستم یا کار پس‌زمینه (Celery). |
| قبل | مقدار قبلی فیلد. |
| بعد | مقدار جدید فیلد. |
| مقدار بریده‌شده | سیستم مقدار بزرگ را کوتاه کرده است. |
| شناسهٔ درخواست | کد یکتای درخواست وب. |

### فیلترها

- دکمه‌های موجودیت: روی یک موجودیت بزنید. فقط تغییرات آن موجودیت را می‌بینید. عدد کنار هر دکمه تعداد تغییرات است.
- کادر «فیلتر نام فیلد»: نام فیلد را بنویسید. مثال: `price`.

---

## ۴. چه کارهایی ثبت می‌شوند؟

نمونه‌ها از داده زندهٔ سیستم:

- ساخت، ویرایش، زباله‌دان و حذف صفحه‌های محتوا (`cms_page.*`)
- ورود، ثبت‌نام و خروج کاربران (`user.login`، `user.register`، `user.logout`)
- فعال و غیرفعال کردن ورود دومرحله‌ای (`user.mfa_enabled`، `user.mfa_disabled`)
- مسدود و آزاد کردن کاربر (`admin.user_blocked`، `admin.user_unblocked`)
- ساخت کاربر توسط مدیر (`admin.user_created`)
- تغییر نقش و دسترسی (`rbac.*`)
- تغییر تنظیمات (`settings.*`)
- رویدادهای تطبیق حساب (`RECONCILIATION_*`)
- تغییر قیمت، موجودی و تخفیف (تب دوم)

---

## ۵. نکته‌های مهم

۱. این صفحه فقط نمایش می‌دهد. هیچ دکمه‌ای داده را عوض نمی‌کند.

۲. دکمهٔ «بروزرسانی» فهرست را از سرور دوباره می‌خواند.

۳. هر رویداد یک شناسهٔ درخواست دارد. برای پیگیری پشتیبانی مفید است.

۴. «قبل» و «بعد» هر دو ممکن است خالی باشند. رویدادهایی مثل ورود کاربر مقدار فیلد عوض نمی‌کنند.

۵. اگر جدول خالی است، یعنی هنوز کار ثبت‌شده‌ای نیست. تغییرات پس از ویرایش قیمت، تخفیف، مالیات یا موجودی اینجا می‌آیند.

---

## ۶. واژه‌نامه

| واژه | معنی |
|---|---|
| رویداد | یک کار ثبت‌شده در سیستم |
| عامل | کسی یا چیزی که کار را انجام داد |
| منبع | نوع چیزی که تغییر کرد |
| عملیات | نام کار. مثال: `cms_page.updated` |
| موجودیت | نوع رکورد در تب دوم. مثال: محصول |
| فیلد | یک ویژگی رکورد. مثال: `price` |
| ردیف | یک خط در جدول |
